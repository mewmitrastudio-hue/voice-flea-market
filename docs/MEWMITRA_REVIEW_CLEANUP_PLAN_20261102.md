# MewMitra 審査用アカウント：最終整理計画（未実行）

作成日：2026-11-02
状態：計画・ドライラン書式のみ。実データの閲覧、変更、削除は一切行っていない。

## 目的と前提
- Apple審査担当者が迷わず主要機能を確認できる状態へ整理する。
- 「新規に近い画面」と「履歴・会計記録の消去」は別。ログイン情報、審査に必要な最小限の商品・操作導線、法定/会計/監査上必要な記録、未解決取引を保持する。
- MewMitraはアカウントの呼称であり、メールアドレス・UIDはまだ同定していない。類似名のアカウントを推測で対象にしない。
- この文書は操作承認ではない。対象を確定したドライランの一覧を提示し、不可逆な変更は個別の最終確認を得てから行う。

## 実行前の本人・対象照合
1. 権限ある管理画面で審査用アカウントの正確なUID、確認済みメール、表示名を照合する。認証用秘密情報は本書に記載しない。
2. 利用者に審査用アカウントであることと保持するログイン経路を確認する。
3. 各対象の所有者UIDと関連する相手・取引・決済・配分・返金・出金・Apple注文を読み取りで照合する。
4. 「テストらしい名前」「少額」「古い」「画面上完了」だけでテスト対象と判断しない。環境、作成目的、相手の権限、関連証跡が揃わない対象は保留。
5. 作業直前のデータを再取得し、ドライランからの追加・変更があれば差分を再承認対象にする。

## 分類と許される整理の候補

| 分類 | 基本方針 | 必要な条件・留意点 |
|---|---|---|
| 不要な試験出品 | 可能なら非公開化・アーカイブ等の可逆操作を優先 | 所有UID一致、審査用で不要と確認、未完了注文・納品・返金との関連なし、復元手段確認。削除を既定にしない |
| 審査に残す出品 | 最小限のみ保持 | 既存の1000円・1500円音声購入、Boost確認用素材を候補に、実際のIAP対応・公開可否・必要操作を照合する。「3商品必須」と決めつけず、既存商品と試験手順から件数を確定 |
| テスト用メッセージ | まず本人側表示の整理・アーカイブが可能か確認 | 相手の表示や履歴を消さない。相手の同意・共有影響が不明なら変更しない。取引証跡を含む会話は保全 |
| 通知・既読状態 | 本人側の表示整理に限って検討 | 実際の未対応事項を既読化して隠さない。サーバー記録と画面表示の区別、未処理通知の保持を確認 |

| 未完了取引・返金調整・精算待ち | 保持・整理対象外 | 出品の非公開化で関連導線を壊さない。退会制限を迂回しない |
| 審査ログイン・権限 | 保持 | パスワード変更・認証解除・権限変更を整理に混ぜない。審査担当者がログイン可能なことを別に検証 |
| 退会デモ | 審査用MewMitraでは実行しない | 別途明示的に許可された使い捨て試験アカウントを使う。作成/本人確認/削除の可否と対象UIDを確認し、金銭・相手への影響がないことを検証 |

## 検証・停止条件

### 変更前
- [ ] アカウントUID/メール/審査用途が一致する。
- [ ] 全対象IDに所有証拠、環境証拠、関連取引の照合結果がある。
- [ ] 審査に残す素材とログイン手順が確定している。
- [ ] 不可逆操作は対象ID・内容・影響を提示して最終承認済み。
- [ ] 試験対象以外・他人側表示・金融記録に影響しない。

### 変更後（承認された操作が実行された場合のみ）
- [ ] 各対象IDを再取得して、意図した状態変化だけを確認する。
- [ ] 件数の前後差と対象ID一覧がマニフェストに一致する。
- [ ] ログイン可能、最小素材の表示・価格・サンプル再生・主要導線が残る。
- [ ] 金融/返金/精算/銀行証跡と未確定Apple注文の識別子・関連付けが不変。
- [ ] 相手側会話・納品・受取導線が失われていない。
- [ ] 未対応通知・未完了取引が隠れていない。
- [ ] 不明な応答は成功扱いせず、再送/再削除せず現状を確認する。

UIDの不一致、所有権不明、実取引との関連、相手への影響不明、未精算・返金調整・未確定Apple注文、承認範囲からの差分があれば、その対象の操作を停止する。整理によってリリースゲートを消去・回避しない。
